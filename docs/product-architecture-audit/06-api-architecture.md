## 2. Conventions observed

| Topic | Observation | Evidence |
|---|---|---|
| Style | REST/JSON, resource nouns, action sub-resources (`/:id/launch`, `/takeover`) | controllers |
| Validation | Zod schemas from `@leadpilot/validation` via `ZodPipe` on body/query; params via `ParseUUIDPipe` | `common/zod.pipe.js` |
| Error contract | `{ code, message, requestId }` from `AllExceptionsFilter` | `common/http-exception.filter.ts` |
| AuthN | HTTP-only cookie or `Authorization: Bearer`; refresh rotation; session revocation checked per request (Redis-cached) | `guards.ts`, `auth/` |
| AuthZ | 41 permission keys; all-of semantics; row-level own/all in services | `PermissionsGuard`, `leads.service.ts` |
| Plan gating | `@RequireFeature('csv_export' \| 'ai_assistant' \| 'web_widget' \| 'lead_portal' \| 'automations' \| 'api_access')` | `PlanGuard` |
| Rate limiting | Global Redis throttler (`THROTTLE_GLOBAL_LIMIT`/min), stricter per-route (`LOGIN_THROTTLE`, `MFA_THROTTLE`, `EMBEDDED_THROTTLE`, `STRICT`), API-key limit `API_KEY_RATE_LIMIT_PER_MIN` | `app.module.ts`, `env.ts` |
| Idempotency | `/v1` via `IdempotencyKey` model + interceptor; **not** on internal mutations (e.g. campaign launch, email send, message send) | `v1.controller.ts`, doc 14 |
| Pagination | Cursor (`take limit+1`) in campaigns recipients and others; list endpoints vary; no single envelope contract verified | `campaigns.service.ts`, mixed |
| Versioning | Only the public API is versioned (`/v1`). Internal API is unversioned and consumed by one first-party client | |
| CSRF | Origin/Referer check middleware (`csrfOriginMiddleware`) rather than tokens | `app.module.ts` |
| CORS | `WEB_ORIGIN` only with credentials; widget routes open to any origin without credentials | `bootstrap.ts` |
| Raw bodies | `rawBody: true` for webhook signatures (Razorpay, Meta, SNS) | `bootstrap.ts` |

## 4. Contract quality assessment

**Strengths**
1. Single source of truth for schemas (`packages/validation`), reused by API, web forms and tests.
2. Consistent error shape with `requestId` surfaced in the UI.
3. Public API has scopes, idempotency keys, rate limiting and a published `/v1/openapi.json`.
4. Webhook receivers verify signatures over raw bytes and de-duplicate by event id (Razorpay; SNS via cert validation; Meta).
5. `security-matrix.test.ts` discovers every controller route at runtime and enforces: reviewed public allow-list, 401 for all non-public routes, a reviewed list of permission-less tenant routes, platform routes guarded, `/v1` guarded, CORS/headers/error-leak/secret-leak checks and an agent-role behaviour matrix.

**Weaknesses and risks**
| # | Finding | Evidence | Severity |
|---|---|---|---|
| API-1 | `/docs` Swagger UI and the full internal OpenAPI (including platform routes) are registered unconditionally, not just in dev | `bootstrap.ts` `setupSwagger` called from `configureApp`, no `NODE_ENV` check | Low (information disclosure) |
| API-2 | Authorisation is split between decorators (124) and in-service checks (77). The gap is **mitigated by `security-matrix.test.ts`**, which fails if a tenant route has no `@RequirePermissions` and is not on the reviewed `SERVICE_ENFORCED` list. Residual risks: (a) the list is a reviewed *exception*, e.g. the four Google Calendar routes are on it with no per-route check; (b) the test only verifies a decorator exists, not that its permission matches the data returned: `email-tracking.controller.ts` declares `lead:read:own` yet returns tenant-wide data (doc 08 S-05) | `security-matrix.test.ts` §"permission declarations"; `google-calendar.controller.ts`; `email-tracking.controller.ts` | Medium |
| API-3 | Platform controller is `@Public()` at class level and opts **in** to `PlatformGuard` per method (fail-open by construction). Mitigated: the matrix test calls every `/platform*` route unauthenticated and requires 401 | `platform.controller.ts:26-72`; `security-matrix.test.ts` "platform routes…" | Low (design smell, covered by test) |
| API-4 | `POST /integrations/google-calendar/connect` takes an un-validated inline body type `{code: string; redirectUri?: string}`; every other mutating endpoint uses a Zod schema | `google-calendar.controller.ts` | Low-Medium |
| API-5 | No idempotency key on internal side-effecting calls (`POST /emails/send`, `POST /campaigns/:id/launch`, `POST /conversations/:id/messages`): double-clicks and retries can duplicate sends | controllers | Medium |
| API-6 | Controllers declared inside `*.module.ts` files (`ai`, `capture`, `channels`, `pipeline`, `roles`, `portal`, `widget`, `support`, `webhooks`, `analytics`, `reports`, `lifecycle`, `health`, `v1`) | file layout | Maintainability |

**Duplicates / redundant endpoints:** none confirmed. `/security/mfa` (user) and `/platform/security/mfa` (admin) are intentional twins; `/privacy/leads/:id/export|erase` (lead-level) vs `/privacy/exports` (workspace) serve different purposes. `GET/PUT /security/workspace` is the MFA policy.

**Oversized controllers:** none large by line count; the weight is in services (doc 10).

## 5. Public API (v1) detail

`/v1/me, /meta, /leads (CRUD, stage, notes), /conversations (read-only), /appointments (list/get/create), /openapi.json`. Scopes: `leads:read|write|delete`, `conversations:read`, `appointments:read|write`. Gaps: no webhooks-management API, no bulk endpoints, no campaign or email endpoints, no documented pagination contract in the evidence I saw. I did not check whether per-key usage is reported.

## 6. Frontend ↔ backend contract

- `orval.config.cjs` generates React Query hooks into `apps/web/lib/api-generated` from the emitted OpenAPI (`pnpm codegen:api`).
- Only `tasks/page.tsx` and `components/crm/task-drawer.tsx` import it; the other 65 consumers use hand-written modules (`lib/crm.ts`, `lib/campaigns.ts`, `lib/ai.ts`, `lib/ops.ts`, `lib/billing.ts`, …) typed through shared Zod schemas.
- Result: types are shared for payload shapes, but routes, query keys and cache invalidation are re-implemented by hand; the generation pipeline costs CI/maintenance without delivering its main benefit. **[Rec]** pick one (see doc 12 §3).
